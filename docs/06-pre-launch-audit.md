# 9. Pre-launch security and quality audit

Audited 23 November 2026 against the pre-launch checklist. Status key:

- **Done**: built into the site and tested.
- **N/A**: does not apply, because this is a static site with no server code, database, logins or admin area.
- **You**: needs a decision, content or account from BrightSteps.

## How the site is built (why many security items are N/A)

The website is plain HTML, CSS and JavaScript files served from a CDN. It has no server code, database, user accounts, passwords, admin pages or API of its own. Form submissions go straight from the visitor's browser to a third-party form service (for example Netlify Forms or Formspree), which stores and emails them. That removes most of the usual attack surface. What remains is protecting visitors in the browser, protecting form data in transit and at the form service, and stopping spam.

## Security checklist

| Item | Status | Detail |

| Hide API keys / secrets off the frontend | Done | No keys exist in the site. A GA4 measurement ID and form endpoint URLs are public by design, not secrets |
| Hash passwords properly | N/A | No passwords are stored. Logins happen only at your host and form service |
| Proper authentication | N/A, then You | No login on the site. Use strong unique passwords and two-factor authentication on your hosting, registrar, form service, email and Google accounts |
| Update dependencies | Done | Nothing to update. Google Fonts are loaded from Google's servers and stay current. Optional: self-host the two fonts for extra privacy and speed |
| Sanitise forms | Done (browser), You (service) | Fields have type checks, required rules, patterns and length caps (254 characters, or 4000 for messages). Resume uploads are limited to PDF and Word, under 5 MB. The form service must also validate on its side; all major services escape submissions in emails |
| Protect against XSS | Done | The page script never inserts user input as HTML (it builds messages with `textContent`). A strict Content Security Policy allows only our own script, plus one exact inline line checked by hash |
| Debug mode | Done | There is no debug mode. One console warning appears only while no form endpoint is set, and it disappears once you connect the forms |
| Full security audit | Done | This document |
| Check for exposed files | Done | Only the `site/` folder is deployed. It contains public pages, CSS, JS, images and config files only. Source, docs and the letterhead are outside it |
| Protect admin routes | N/A | There is no admin area. The template article page is `noindex` and blocked in `robots.txt` |
| Secure API endpoints | N/A | The site has no API. The form service endpoint is protected by that service |
| Check CORS settings | N/A | No API of ours means there is nothing to configure. The CSP `connect-src` and `form-action` allow only the form service |
| Add security headers | Done | `site/_headers` sets CSP, HSTS, nosniff, `X-Frame-Options: DENY`, Referrer-Policy, Permissions-Policy and COOP. It is generated by the build from `src/config.mjs`. I tested the CSP locally: no violations, and fonts, map and forms work |
| Secure database access | N/A | No database. Form submissions sit in the form service account (see the forms and data handling guide) |
| Force HTTPS | Done, then You | HSTS header plus `upgrade-insecure-requests`. Turn on "Force HTTPS" at the host after the certificate is issued |
| Spam protection | Done | Hidden honeypot field, a 3-second minimum time before submit, and the form service's own spam filter. No CAPTCHA, so blind and low-vision users are not blocked |

## Must-do list before go-live

1. Connect the three forms (see the forms and data handling guide). Until then submissions are **not sent anywhere**.
2. If the form service stores data overseas, keep the overseas sentence in the privacy policy. Delete it if all data stays in Australia.
3. Add photos with alt text, real reviews and the team photo, or leave the labelled placeholders until you have them.
4. Turn on HTTPS and two-factor authentication on every account.
5. Add the GA4 ID if you want analytics.
6. After launch, test each form end to end and run PageSpeed Insights.
